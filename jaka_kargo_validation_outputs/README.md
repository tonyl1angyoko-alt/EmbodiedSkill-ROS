# JAKA/Kargo integration evidence

`integration_scenarios.json` is generated by the ROS2 Humble
`validate_jaka_kargo` harness. It starts a separate legacy-compatible stub process
that uses the exact generated `jaka_toolbox_interfaces` and `jagv_interfaces` ROS
types. It does not load the vendor SDK and does not connect to robot hardware.

The evidence supports the integration adapter and schema boundary only:

- J1/J6/J7/J8 exercise lift, single-arm, AGV navigation, head, and waist mappings;
- J2 preserves command receipt vs measured outcome separation;
- J3 rejects a bilateral semantic mismatch before transmission;
- J4 blocks motion when whole-robot emergency-stop evidence is unavailable; and
- J5 records that a client-side Service timeout is not reliable cancellation; and
- J9 confirms that navigation Service success without a newer target-valued
  odometry observation is rejected.

Status: legacy-compatible adapter runtime `ROS2-RUNTIME-VERIFIED`; JAKA node runtime
and JAKA hardware `UNVERIFIED`.
